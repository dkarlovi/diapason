# Glide output and editing

The user approved integrating the curved-note study in `dev/glide-study.html`, including bend handles and the corrected audible smooth-range behavior.

- One Glide control: 0 fixed pitches, 0.2 coarse discrete steps, 0.4 semitone steps, and 0.41–1 smooth bends. Values below 0.4 snap to the three stops. In the smooth range, the fraction of each point-to-point interval used for movement is `0.08 + 0.92 * (glide - 0.4) / 0.6`. Lower values hold the preceding pitch longer; 1 uses the full curve. Point pitches and arrival times remain fixed.
- A note's filled ribbon follows sounding pitch. Stepped output draws separate blocks belonging to the same logical note. Its target pitch remains visible as a faint reference. Selection, note transposition, mutes, edit stripes, hit testing, and viewport framing account for the contour.
- Selecting a note in smooth mode exposes bend points. Drag up/down for pitch and left/right for position. End position and destination offset remain fixed. Keyboard controls provide equivalent adjustment. A gesture creates one undoable edit; Escape, lost capture, and a second touch cancel it. Reset bend restores automatic interpretation.
- Source curves are normalized positions and semitone offsets from a note's target; shared explicit types live in `*.type.ts`. A shared pure evaluator drives drawing, browser playback, external MIDI and MIDI export. Curves have 2–32 finite points, positions strictly increasing from 0 to 1, offsets within ±48 semitones, and a final offset of zero.
- Preserve source PCM and existing interpretation versions. Existing preset values remain frozen, with Glide historically defaulting to zero. Interpretation 3 opts into contour-aware segmentation and curve storage; existing v1/v2 tunes remain byte-compatible. Using the new control, including explicit zero, opts into v3. Changing the output amount within v3 does not change segmentation.
- Within v3, stable pitch regions support discrete notes; connecting motion attaches to its destination region. Articulation and protected edit boundaries remain authoritative. Steadiness filters small movement and wobble; it must not absorb clean short chromatic steps merely because they are short. The reviewed Moon regions 4.032–5.013333333333334 are one intended F#6. This is a regression example, not a general merging rule.
- Manual bend edits retain their source segment so re-segmentation cannot discard an edited curve. Whole-note pitch edits transpose the curve; timing edits scale its normalized positions. Saving, versions, WAV restoration, share links and Diapason MIDI preserve automatic and manually edited contours separately.
- Smooth MIDI uses standard MIDI 1.0 pitch-bend messages, a matching RPN bend range, and bend resets. Stepped output uses ordinary note events. Flat legacy output emits identical bytes. Unsupported devices may require matching bend-range configuration; stepped output remains available.
- The Rhapsody example is synthesized demonstration material with approximate expressive timing, not detector ground truth. Verify 41%, 70%, and 100% against actual rendered audio, not just visual differences.

Production validation includes the synthetic contour corpus, the real Moon recording, legacy approved fixtures, malformed curve/version input, edits and undo, sharing/WAV/MIDI roundtrips, all browser instruments, MIDI cancellation/reset, and control alignment at 360px/286px panel widths and phone portrait/landscape. Screenshots stay outside the repository.
